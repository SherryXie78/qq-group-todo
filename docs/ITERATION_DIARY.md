# 问题与改进日志

每一条记录一次使用反馈与对应改进。旧对话缺少逐条可靠时间，因此用“第几次”排序；不以文件修改日期冒充提出需求的日期。2026-11-15 首次回顾整理。日志采用通用称呼，不包含真实群、成员、私人地址或原始聊天。

## 第一次：群消息太多，重要通知被淹没

- 遇到的问题：多个群聊里有大量重复回复，长通知难以快速阅读，重要事项容易遗漏。
- 提出的要求：只读收集选定群，使用已有账号，不注册小号、不发送群消息；AI 筛选重点并整理成可操作的待办。
- 采取的改动：选用 qq-live-digest 引擎，增加本地部署配置、白名单和无发送通道的启动方式，接入 DeepSeek 辅助提取。
- 结果与限制：形成电脑工作台；AI 提取仍可能有误，需要原文核对。原引擎属于上游贡献。
- 本次可学：消息采集、过滤、摘要、任务四个环节各自负责什么。

## 第二次：关闭窗口后，桌面图标无法重新打开工作台

- 遇到的问题：关闭窗口、再点击图标时界面无法出现，也不容易找到程序。
- 提出的要求：保留清楚的桌面入口，能可靠启动和重新打开已有服务。
- 采取的改动：统一桌面启动入口，检查 HTTP 服务是否就绪，复用运行中的工作台并保留启动记录。
- 结果与限制：已有启动修复和检查；后续又收到超时反馈，因此不能把单次修复当作永久无故障。
- 本次可学：网页窗口关闭与后台服务停止的区别。

## 第三次：使用助手时，普通电脑版 QQ 会被挤下线

- 遇到的问题：早期采集方案相当于另开一个电脑会话，影响正常处理群消息。
- 提出的要求：与普通电脑版 QQ 共存；新增需要监控的群可以在界面里输入。
- 采取的改动：私人环境改用共享已有电脑 QQ 的共存接入；增加群列表管理并动态更新白名单。
- 结果与限制：使用者曾确认普通 QQ 可正常查看且没有掉线。采集器受独立许可约束，公开仓库不附带其修改版。
- 本次可学：登录会话、进程和消息事件接口的区别。

## 第四次：重启电脑后，登录二维码过期且无法刷新

- 遇到的问题：登录提示使用过期二维码，点击刷新也无法恢复。
- 提出的要求：重新获取有效登录入口，并避免反复要求扫码。
- 采取的改动：早期登录流程增加二维码有效期、重试与恢复处理；后续共存方案改为使用普通 QQ 的登录状态。
- 结果与限制：历史上已完成扫码和登录确认。旧独立登录方案不再作为当前恢复入口。
- 本次可学：凭据有效期、缓存失效与登录状态不能混为一谈。

## 第五次：以前的任务和漏掉的消息没有进入待办

- 遇到的问题：仅处理新消息，无法方便复查过去一段时间的通知。
- 提出的要求：按群和时间范围审查历史；至少能够手工添加遗漏任务。
- 采取的改动：增加历史审查编排、明确未来截止时间的筛选规则，以及带重复提交防护的手工任务入口。
- 结果与限制：对应模块和测试已存在；真实历史获取取决于采集端可用能力，不保证无限回溯。
- 本次可学：历史查询范围、消息去重与任务新增边界。

## 第六次：电脑关机就漏消息，外出也看不到日程

- 遇到的问题：电脑休眠或关机期间停止采集，手机无法像电脑一样随时访问工作台。
- 提出的要求：能在手机查看，并考虑电脑关机后的持续采集。
- 采取的改动：先实现通过私人连接访问同一工作台；研究独立手机采集和云端分析方案。
- 结果与限制：使用者曾确认手机在流量网络下可刷新。云端与独立手机采集未实施，关机后的持续采集仍未实现。
- 本次可学：手机显示界面与后台采集服务是两种能力。

## 第七次：手机需要额外打开浏览器和连接应用

- 遇到的问题：浏览器顶部和启动画面影响体验，连接需要切换多个应用。
- 提出的要求：一个独立应用入口，连接能力放在应用内部。
- 采取的改动：先调整网页安装体验，再制作带内置连接的私人 Android 容器，处理前台恢复和可信来源导航。
- 结果与限制：使用者曾确认独立界面正常显示。完整第三方 Android 运行件未纳入公开仓库；连接恢复仍需改进。
- 本次可学：PWA、WebView 容器与原生后台连接的区别。

## 第八次：任务太啰嗦，读完还是不清楚要做什么

- 遇到的问题：待办保留了太多修饰词，标题长，关键信息不突出。
- 提出的要求：时间、地点、做什么分别清楚显示，标题允许多行。
- 采取的改动：增加任务呈现结构和简明卡片，把原文放在可展开的依据中。
- 结果与限制：已有卡片结构；不明确的地点需要提示待核对，不能凭空生成。
- 本次可学：原始文本、结构化数据和界面呈现的区别。

## 第九次：一个活动的练习和考试被压成同一个截止时间

- 遇到的问题：跨天活动有多个阶段，单个日期不足以表达任务。
- 提出的要求：保留时间范围、阶段性 deadline，分别跟踪完成情况。
- 采取的改动：增加阶段任务模型、原文日期校验、逐阶段完成和日历导出。
- 结果与限制：已有阶段测试；仍需防止把不同阶段的日期和原文串在一起。
- 本次可学：一项任务可以具有多个里程碑，单个 deadline 无法覆盖全部情况。

## 第十次：纠错只有选择题，改错后任务还可能被丢弃

- 遇到的问题：错误常常是时间或内容有误，而不是整项任务不需要。
- 提出的要求：输入文字说明原因，选择是否保留，修正后继续提醒。
- 采取的改动：加入自由文本反馈、默认保留、后台 AI 审查、变更记录与撤销。
- 结果与限制：使用者曾确认手机能看到输入框；模型修正内容仍需要核对。
- 本次可学：纠错、删除、审计和撤销应有明确不同的含义。

## 第十一次：今天的任务被归到以后，首页提示也不友好

- 遇到的问题：日期分类与北京时间不一致，连接报错占据首页主要位置。
- 提出的要求：统一北京时间，显示今日日期和距离截止的天数；建议与错误提示分开展示。
- 采取的改动：增加统一时间转换、倒计时、每日建议缓存和独立错误区。
- 结果与限制：已有时间转换测试，使用者曾确认新版日期和页面出现；未覆盖的文本日期情况继续跟踪。
- 本次可学：时间戳、带时区时间和本地日期不是同一种数据。

## 第十二次：一条通知里的多个作业被合并，同一任务又重复出现

- 遇到的问题：多项任务混成一张卡，重复通知又可能产生多张卡。
- 提出的要求：既能拆分不同事项，也能比较已有待办并合并重复通知。
- 采取的改动：引入独立事项提取、候选检索、模型关系判断和保守的合并条件，保留变更与撤销。
- 结果与限制：有相关回归测试；仍不能承诺所有文本都能正确拆分或去重。
- 本次可学：拆分与去重是两类问题，不能只用标题相似度决定。

## 第十三次：想在同一处直观看课程和任务

- 遇到的问题：列表不容易看出某天的课程与安排。
- 提出的要求：增加日历页，或与手机日历互联。
- 采取的改动：接入 FullCalendar，增加本地课程编辑、任务日历与 iCalendar 导出。
- 结果与限制：使用者曾确认日历页出现。没有自动获得系统日历权限，也没有未经确认写入外部日历。
- 本次可学：显示日历、导出日历与写入系统日历分别需要什么条件。

## 第十四次：启动出现超时，QQ 在线但工作台提示未连接

- 遇到的问题：启动窗口报告 TimeoutExpired，采集提示与实际 QQ 使用状态不一致。
- 提出的要求：修复启动与状态判断，增加登录板块。
- 采取的改动：使用 HTTP 就绪探测，校验采集进程身份；区分登录、等待、停止和状态过期，增加检测与恢复入口。
- 结果与限制：使用者曾确认未连接提示消失；状态过期不能直接判定 QQ 已退出。
- 本次可学：健康检查、缓存状态和真实登录状态的区别。

## 第十五次：完成任务缺少趣味反馈

- 遇到的问题：完成任务只有状态变化，缺少持续使用的正反馈。
- 提出的要求：完成加积分，通知流换成宠物页，上传形象并兑换互动。
- 采取的改动：增加本地积分账本、完成 / 撤销规则、幂等互动、头像裁剪与去元数据处理。
- 结果与限制：有积分与头像测试；新版手机安装和图片选择仍需真实设备确认。积分不是付费货币。
- 本次可学：数据库事务与幂等为什么能避免重复扣分。

## 第十六次：新版手机安装包下载失败

- 遇到的问题：手机浏览器只显示“下载失败”。
- 提出的要求：能看到下载进度并完成更新。
- 采取的改动：增加过期下载凭据、分段重试、进度显示和下载后 SHA-256 校验。
- 结果与限制：使用者确认已看到进度并正在下载，尚未确认此次安装完成；不能把下载进度等同于安装验收。
- 本次可学：身份认证、断点分段和文件校验分别解决什么问题。

## 第十七次：手机长期停留在旧离线缓存

- 遇到的问题：手机持续显示离线缓存，内容停留在很久以前。
- 提出的要求：解决互联问题，让恢复连接后能看到最新待办。
- 采取的改动：已登记排查目标；本轮尚未完成原因确认和程序修复。
- 结果与限制：仍待排查。后续需实际验证连接、认证、缓存和前台恢复，不能提前记为已修复。
- 本次可学：离线可用与在线数据新鲜度是两种不同的指标。

## 2026-11-15：建立项目库、逐次日志并迁移存储

- 遇到的问题：项目成果散落，难以讲清每次改进；C 盘持续占用空间。
- 提出的要求：独立 GitHub 项目仓库，彻底去掉私人信息；逐次日志可用于视频和面试，在本机方便查看；程序和记录迁往 E 盘。
- 采取的改动：准备源码白名单和隐私检查、保留上游声明、建立逐次日志与本机阅读页，迁移运行目录并核对文件哈希。
- 结果与限制：132 个脱敏文件已发布并核对内容哈希；重点回归 71 项通过，全套 719 项中仍有 32 项失败、8 项错误、1 项跳过。建立 Issue #1 跟踪手机缓存，Issue #2 跟踪历史测试。程序已迁至 E 盘并验证启动，14,244 个文件完成迁移校验；Codex 正在使用的记录仍需退出应用后切换。
- 本次可学：版本控制、发布副本、数据隐私和存储迁移验证。
